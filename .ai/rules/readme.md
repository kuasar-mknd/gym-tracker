# Readme

## Le README se tient à jour dans la PR qui le rend faux, à commencer par les variables d'environnement
Décision du propriétaire du dépôt (2026-10-02) : le README est maintenu, pas réécrit de temps en temps. Toute PR qui ajoute, renomme, retire une variable d'environnement ou en change le rôle ou la valeur par défaut — `env()` dans `config/`, `${…}` dans `docker-compose.prod.yml`, `ENV` du `Dockerfile`, `entrypoint.sh`, le Caddyfile, une `VITE_*` du front, un secret de CI — met à jour dans la même PR la section « Variables d'environnement » du README et `.env.example`. Même chose pour tout autre fait du README que la PR rend faux : nombre de tests, seuils, commandes, services, versions. `LeReadmeDocumenteLesVariablesTest` (tests/Feature/Conventions) refuse une variable de `docker-compose.prod.yml`, de `.env.example` ou un secret de CI que le README ne nomme pas entre accents graves, et une variable du tableau « Production » que la composition ne transmet pas — le défaut d'origine : `HORIZON_ALLOWED_EMAILS` et `ADMIN_INITIAL_PASSWORD` étaient documentées pour la pile et n'atteignaient aucun conteneur. Une variable lue par `config/` sans être transmise par la composition n'a aucun effet en production ; la transmettre, c'est l'ajouter à `docker-compose.prod.yml` avec `${NOM:-défaut}` (une variable oubliée sans défaut arrive vide, et Laravel prend la chaîne vide, pas le défaut de sa configuration). `DocumentationSansDeriveTest` tient déjà les chemins et les versions majeures.

## OPcache de la ligne de commande : un ini propre à worker et scheduler, jamais à app
Réglé le 2026-10-05 (#1968). `docker/php-prod.ini` sert le serveur web (OPcache, JIT `tracing`, `validate_timestamps=0`) et laisse OPcache coupé en ligne de commande. worker et scheduler chargent en plus `docker/php-cli/zz-cli.ini` par `PHP_INI_SCAN_DIR: ':/app/docker/php-cli'` (le `:` de tête garde le dossier par défaut, donc les extensions et php-prod.ini). Trois pièges : sans `opcache.jit=disable`, le cache fichier n'est jamais écrit et chaque commande ralentit ; sans `validate_timestamps=1`, le cache fichier d'un démarrage précédent servirait la configuration que `config:cache` vient de réécrire ; et un dossier de cache absent ou non inscriptible fait refuser à OPcache de démarrer (toute commande PHP sort en 254, sondes de santé comprises) — l'image le crée pour www-data, et `read_only: true`, ou un `tmpfs` ou un volume monté sur ce dossier ou sur l'un de ses parents (/tmp), le figerait ou le cacherait. Ne jamais poser la variable dans `app` : le serveur lancé par Octane hérite de l'environnement et perdrait son JIT. `LOpcacheSertLaLigneDeCommandeTest` tient la composition (dont ces montages dans worker et scheduler), l'ini et le `Dockerfile` ; le job `demarrage` vérifie l'ini dans l'image construite.

## Réseaux de la composition : une sortie pour qui envoie, aucune pour db et redis
Réglé le 2026-10-08 (#2019). `backend` est interne, donc sans aucune route vers l'extérieur. Le serveur web, Horizon et le planificateur envoient tous : app depuis une requête, worker les notifications en file (push, courriels, avis des sauvegardes lancées du panneau, dont le job tourne dans Horizon), scheduler les alertes de santé, synchrones ; si la pile transmettait `HORIZON_HEARTBEAT_URL` ou `SCHEDULE_HEARTBEAT_URL` (elle ne le fait pas), les appels de ces URL partiraient aussi de scheduler. Les tâches de sauvegarde planifiées demandent `--disable-notifications` : aucun avis n'en est attendu, elles ne sont pas une raison de la sortie de scheduler. Chacun doit être sur un réseau non interne (app sur `frontend`, worker et scheduler sur `sortie`, réseau à eux pour ne pas être joignables par ce qui se brancherait sur `frontend`). worker et scheduler sont restés sur `backend` seul jusqu'à la 1.6.0 : aucune notification push ni alerte `HEALTH_TO_ADDRESS` ne pouvait partir, sans que rien ne le signale. db et redis n'ont rien à joindre hors de la pile : `backend` seul. Un service sans `networks`, ou avec une liste vide (`[]`, `{}`), est sur `default`, qui sort ; `network_mode: service:<x>` lui donne les réseaux de x, et la garde refuse `container:<x>`, qu'elle ne peut pas lire. `LesEnvoisOntUneSortieTest` (tests/Feature/Conventions) tient les deux bouts ; `compose.yaml` (développement) n'a qu'un réseau, non interne, et n'est pas concerné.
