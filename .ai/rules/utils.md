# Utils

## La file hors-ligne : quatre verdicts, l'ordre des écritures, et deux évènements à écouter
`classifySyncError` rend quatre verdicts : `offline` (réseau absent, l'écriture est en file), `auth` (401/419, la session ou le jeton CSRF ont expiré : porte fermée, pas refus), `permanent` (4xx, à faire remonter), `transient` (5xx, 429, à réessayer). Depuis #1667 (2026-09-03), un `auth` laisse la file intacte, incrémente `authAttempts` sur l'entrée et émet `sync:auth-required` ; trois portes fermées de suite classent l'entrée refusée (`recordFailure`) pour ne pas bloquer la file. Depuis #1963, un `transient` pendant le vidage fait de même : l'entrée reste en tête, `transientAttempts` et `prochainEssai` sont notés sur elle, une relance est programmée (5 s, puis le double à chaque échec, ou le `Retry-After` d'un 429, plafonné à cinq minutes), et aucun autre déclencheur ne la devance ; six échecs passagers la classent refusée. `http()` garde pour cela les en-têtes de la réponse sur `ErreurHttp`. `request()` vide la file avant toute écriture directe et, si elle ne se vide pas, range la nouvelle écriture derrière : c'est ce qui empêche une valeur ancienne rejouée d'écraser une valeur saisie en ligne. `saveQueue()` émet `sync:storage-full` au lieu de lever quand le quota est atteint ; le constructeur lit un stockage corrompu comme une liste vide. Dans les tests, le singleton vide la file à la construction : attendre `service.pending` avant de compter les tentatives (`chargé()` dans `syncService.test.js`).

## La file appartient au compte, pas à l'appareil
Depuis #1964, chaque entrée de `offline_sync_queue` et de `offline_sync_failed` porte `compte`, l'identifiant de l'utilisateur connecté quand l'écriture est partie. Le service le lit dans la page rendue (`script[data-page]`) à sa construction, puis à chaque `inertia:navigate` (`definirLeCompte`) ; seules les entrées du compte connecté se vident, se comptent (`enAttente()`) et s'annoncent (`failedRequests()`). Sans compte connu, rien n'entre en file : l'échec réseau remonte tel quel. Une entrée sans `compte` (écrite avant #1964) n'est jamais rejouée et s'efface au chargement. La déconnexion (`seDeconnecter`) garde la file du compte qui part, efface ses refus et les brouillons `draft_set_*`, et laisse un nombre dans `sessionStorage` que `GuestLayout` affiche une fois (`Utils/ecrituresGardees.js`). Dans les tests, `tests/js/utils/fileHorsLigne.js` rejoue un chargement : page posée, singleton neuf, écouteurs de l'instance précédente retirés.
